Why I built it

Published lecture slides rarely include the explanations you'd get by sitting in class. When I missed a lecture or reviewed one at night, I kept asking ChatGPT, Gemini, or Claude for the same thing: a slide-by-slide explanation of what the slides leave out, and the reasoning behind the harder math. It worked, but I was always switching between the lecture and the chat window. So I built a tool that shows each slide next to its explanation, and lets me save the summary for later.

01 · Parallelization

All slides at once

Every slide is explained concurrently, sent as an image plus its text and its neighbours' text, so diagrams and right-to-left slides read correctly.

02 · Evaluator-optimizer

A second model checks

A reviewer compares each explanation with the slide and returns feedback if it finds an error, which cuts down on hallucinated details.

03 · Prompt chaining

One lecture-level view

The finished explanations feed a final call that writes the summary, glossary and quiz.

Guardrails

  • Page limit and at most one revision per slide keep cost predictable
  • Live token counter shows exactly what each lecture costs
  • One failing slide never stops the rest of the lecture
  • Password protection when deployed; API keys kept out of the code
  • Offline mode for testing the interface without spending credit

Design choices

  • Slides sent as images, not just text, because Hebrew text layers in PDFs are often garbled
  • Pages that only build up the next slide are detected and skipped
  • Notion export stays manual, so I choose which lectures to keep and where
  • The model is configurable, so it can be swapped for a cheaper or stronger one
